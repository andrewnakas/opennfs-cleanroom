## Engine facts (verified from source: OpenNFS dcd9197, LibOpenNFS 3ebd326)
- ~16.6k lines C++20, OpenGL 3.3 + GLFW + GLEW + Bullet + ImGui + FreeType + g3log. MIT.
- Loads tracks and cars of the PC series generations 2 to 4 (and two PS1 ones) through LibOpenNFS. Generation 3 is the default and best supported path; that is what this build uses.
- Physics: Bullet raycast vehicle (default) or a reimplemented "HS" model (`--hs`).
- **Missing upstream, added by this port**: any audio, lap counting / race rules / finish, a HUD (only an ImGui debug window existed),
  usable menus (upstream menus need retail front-end files), a working AI on closed circuits (it reset itself at every lap wrap and was
  capped at 100 km/h), frame-rate independent steering.
- The engine repo bundles art of unclear origin (sky textures with an `index.fsh`, an icon named after the retail game, skydome TGAs,
  menu PNGs). **None of it is used**: everything is regenerated by `games/opennfs/build_assets.py`, and the taint scan checks against it.

## Decisions (log)
- **Web route**: direct emscripten build (the engine is a PC OpenGL program). WebGL2 = GLES3. No emulator.
- **Port mechanics**: engine stays pristine in `D:\n64work\opennfs\OpenNFS`; the port tree is `pristine + ports/opennfs/overlay + ports/opennfs/patches.py`
  written by `ports/opennfs/prepare.py` (incremental, also copies LibOpenNFS so its sources can be patched).
  GLEW -> header shim on GLES3; g3log (threads) -> single-threaded shim; FreeType from the emscripten port; GLFW = emscripten's.
- **Rendering changes**: GLSL ES 3.00 fixes; new track and car fragment shaders (directional sun, sky ambient, 4-tap cascaded shadows,
  haze; the upstream ones gave the sun no colour and ran 36 lights per fragment); texture array sized to the layers in use (upstream
  allocates 512 layers); real aspect ratio and a 0.3 m near plane; clouds wrap.
- **Gameplay layer** (`overlay/src/Race/RaceRules.*`, `Agents/*`, `Camera/CarCamera.*`): grid, 3-2-1 countdown, laps by sector order,
  timing, positions, finish and results, wrong-way notice, automatic recovery (roof, wedged, out of the world), three camera views.
- **AI** (`RacerAgent`): pure pursuit on the virtual road, speed planned from the curvature of the road positions and braking distance,
  lane kept within a lane's width of the driving line, **raycast lane changes** around scenery standing on the driving line (classic
  circuit 1 has a traffic island exactly on it), reverse / reset when stuck.
- **Handling** (constants in `patches.py`, section "car handling"): tyre friction 1.9, softer long-travel suspension, brakes on four wheels,
  speed-sensitive steering lock, downforce, lateral damping and a yaw assist. Tuned blind with the test autopilot (clean laps); it
  needs a human pass for feel.
- **Names**: public title "Open Road". Cars "Clean Coupe / Hatch / Wedge" by the fictional "Cleanroom Motors": original lofted shapes, not based
  on real vehicles. Classic circuits are called "Circuit 1" to "Circuit 9" (retail titles are not used). Engine defaults that named retail car
  folders are patched. Log and assert strings are scrubbed of retail titles at port-tree build time; `__FILE__` paths are remapped.
- **Retail cars are not used at all** (not even debadged geometry): the shapes themselves are the makers' designs. Car physics numbers
  were therefore not taken either. Say so if you want debadged kept car geometry instead.
- **Kept facts for classic circuits** (per the scope in CLAUDE.md): FRD/COL geometry, collision, texture mapping, virtual road, object placement
  and motion; CAN camera path; AI speed table; the two sky colours of the horizon file.
  - *Interpretation to confirm:* the geometry files also hold a colour per vertex (baked lighting). That is art, so it is **not** kept as is:
    it is reduced to one average colour per track block / per object (blended between neighbours), alpha to 2 bits. If you want none of it,
    set them to white in `games/opennfs/dirty/kept_geometry.py` (one line) and re-run the two scripts.
  - *Interpretation to confirm:* texture alpha is kept at full resolution with 2 bits (your usual "2-bit alpha outline"); the override text says
    "alpha class". Changing it to a per-texture class is a small edit in `extract_spec.py`.
  - Camera paths and AI speed tables are byte-identical to the game's (they are pure numbers); the taint scan reports them as kept.
- **Textures of classic circuits**: regenerated from the 4x4 colour grid + alpha only (`clean_tracks.py`): bicubic colour field + procedural
  detail picked from the coarse colour (stone / foliage / earth / smooth). Stored 16-bit like the originals.
- **Delivery**: core pack 1.1 MB + engine 3.5 MB (about 1.2 MB over the wire) + one pack per track (0.6 to 1.6 MB), fetched on first use.
- **Sound**: no retail audio is read at all. Engine note, tyres, wind, impacts, signals and a music loop are synthesised with WebAudio.
- Public repo is a curated export (port, generators, tools, ledger). CLAUDE.md, the playbooks, `reference/` and the shared `cleanroom/`
  library (unused by this game) stay local.

## Gates
- `python tools/taint_scan.py`: manifest check, identity check, look-alike images, and for rebuilt textures a detail-correlation test against
  the retail texture each one replaces (after removing the kept grid). Last run: 101 clean files, 1858 clean images, 1312 reference files, **0 failing**.
- `python tools/name_scan.py <site> <clean>`: publisher / game / car-maker names in the output. Rule used: engine identifiers
  (`OpenNFS`, the `NFS_3` format enum and folder, parser class names inside mangled RTTI) are allowed, human-readable titles are not.

## Layout
- `ports/opennfs/` CMake project, patch list, overlay (shims, web main loop, race rules, AI, camera, shaders), page (`web/`).
- `games/opennfs/` generators: `nfsfmt.py` (format writers), `synth_track.py`, `synth_car.py`, `proctex.py`, `clean_tracks.py`, `build_assets.py`.
- `games/opennfs/dirty/` the only code that reads the game folder (`extract_spec.py`, `kept_geometry.py`, `fshread.py`, `contact_sheet.py`).
- `tools/`: `build_web.sh` (prepare + ninja, locked, one-screen summary), `make_site.py`, `taint_scan.py`, `name_scan.py`,
  `drive_test.sh` (headless race with telemetry table; `?autopilot=1&ff=60` drives the player's car through the normal controls).
- Work dirs on D: `D:\n64work\opennfs\{OpenNFS,port,build,clean,spec,site,shots}` (about 2.5 GB including the disc image).

## Known issues / next
0. **Start-up crash on some classic circuits: mitigated, root cause NOT found.** (session 2, 2026-10-10)
   - **Could not be reproduced today.** About 130 loads over five builds with the stock allocation operators, including the
     unmodified commit that crashed yesterday (same sources, same physics library, same data), all reached "ready". Yesterday's
     crashes were real (two trap stacks are on record), so the fault depends on something outside the build that I have not
     identified; yesterday the machine was short of memory and busy, today it was not. A stack-overflow trap build
     (`cmake -DWEB_STACK_CHECK=ON`) was also clean on all 12 circuits.
   - **The test harness produced false failures.** The headless browser sometimes returns an empty console (its profile folder is
     still locked by the previous run), and under pressure the software WebGL context can be lost. Several of yesterday's
     "not ready, no error line" results were probably this. `tools/dev/loads.sh [rounds] [tracks]` retries and labels each
     load R (ready) / C (trap) / H (hang) / - (browser gave nothing).
   - **Shipped mitigation (approved by the owner on 2026-10-10):** zero-filling C++ allocation operators
     (`-DWEB_FILL=0x00 -DWEB_FILL_MODE=WEB_FILL_KEEP_FREED`). Builds with replaced operators have never failed a load
     (about 45 loads yesterday, 49 of 49 today on the release configuration).
   - **Hardening added today** (real upstream defects found by reading the loaders; none was shown to be the cause, their
     counters never fired on our circuits): collision polygons indexed vertices with signed bytes; mesh de-indexing did not
     check indices (`BADINDEX` console line if it ever happens); colour names indexed past the list; the physics debug line
     buffers asked for 57 MB each instead of 2.4 MB (a likely cause of lost WebGL contexts on small devices); telemetry text
     buffer length clamp. A trap now shows a message to the player instead of a frozen screen. The heap walker only runs with
     `?heapwalk`.
   - Read and found clean (do not re-read): `Car`, the agents, `RaceSession`, `RaceRules`, `CarCamera`, `PhysicsManager`,
     renderers, shader classes, the track and car file structs.
   - Not yet tried: unchecked writes in the texture decoder (`QfsCompression.cpp`, `FshTexture.cpp`), texture upload size taken
     from a different file than the pixels (`GLTexture.cpp:118`), a slow-device run (CPU throttling through the browser debug
     protocol; my attempt at a tool for it was unreliable and is not in the repo), fills for aligned `new` and the physics
     library's own allocator.
1. (done) Text inside classic-circuit textures is re-typeset from briefs; look at `games/opennfs/sign_sheet.py` output for wrong guesses.
2. Classic-circuit road surfaces look blotchy (coarse grid colours); consider flattening road textures towards their mean.
3. Handling and AI pace need a human test drive. Opponents do not avoid each other, only scenery.
4. Performance on phones is untested (headless tests run on a software rasteriser). The page has `?noshadow=1`.
5. Only the first classic circuit has been raced end to end by the autopilot; the others load through the same path but are not all verified.
6. Night / weather variants of the classic circuits and traffic are not built.
